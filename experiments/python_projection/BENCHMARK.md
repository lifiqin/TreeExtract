# Python 与 C# 投影试点：一次本机对照

## 测试范围

2026-11-18，在 Windows 11、Intel Core i9-13900HX、CPython 3.12.14、.NET 10.0.15 上运行三次。比较的是本分支现有 Python 标量实现和从同一份 `src/Proj.cs` 编译的 C# Release 实现，**不是**整套桌面软件、图像渲染或识别模型。

- 数值：同一批合成参数，512 个世界方向到照片坐标、512 个照片点反算世界方向；另取 25 个合成方向制作可视化。参数使用 `d=1.0`。
- 计时：每种算法先预热；每次计算处理同样的 512 组输入，循环 400 遍，每轮 204,800 次调用；七轮交替测量次序，表格使用每轮每次调用时间的中位数。
- 计时包含各实现自己的调用、循环和结果汇总，不包含进程启动、编译、JSON 输入解析、跨进程通信和图像显示。两边的结果汇总在每轮核对，避免无结果的空循环。

## 一次复测结果

| 操作 | Python 中位数 | C# 中位数 | 该项 C# / Python 速度比较 |
| --- | ---: | ---: | ---: |
| 世界方向 → 照片坐标 | 0.902 微秒/次 | 0.0408 微秒/次 | C# 约快 22.1 倍 |
| 照片坐标 → 世界方向 | 1.800 微秒/次 | 0.0840 微秒/次 | C# 约快 21.4 倍 |

另外两次独立运行分别约为 19.7 / 22.2 倍和 21.2 / 22.0 倍。512 个世界方向样本在该环境下的数值结果相同，按 4000×3000 画幅换算最大坐标距离差为 0；512 个逆投影样本的角度差也为 0。这只是**该批输入和当前环境**的结果，不保证所有浮点输入、机器或运行时逐位一致。原有 3,632 组合成输入的一致性测试还覆盖两种 `d` 和更多边界。

## 如何解读

本机的纯标量实现中，现有 C# 计算明显更快；但该实验没有测试 NumPy 等批量化、其他 Python 优化方式或完整应用的响应时间，也没有比较启动、IPC、图片解码、模型推理及打包成本。Python 与 C# 使用相同的数学公式，因此本次结果不能证明任何一方更能识别树或更准确定位真实树木。是否迁移整个后端仍需独立的端到端性能、真实数据和人工真值验证。

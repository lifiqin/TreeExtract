## 1. 背景与问题

- 现状红圈锚点由 `TrunkMarkH(H) = clamp(0.042H, 0.42, 0.75)` 给出高度（约 0.42~0.75 m），横向取 `trunk.csv` 的 `Tux/Tuy`（缺失时退回树心方位 + 2.7° 历史修正）。该高度是当年为「避免落到草丛 / 分叉枝杈」刻意压低的，**用户明确反馈「红圈太靠下、部分树左右偏移」**。
- 单帧口径的固有局限：标注几何全部由**当前主帧**的 Metashape 姿态 + 理论树心/干心坐标反算得出；近距树（<4 m）下，树心（树冠重心）与干心的 0.04~0.43 m 差异会被放大成 2~3° 横向偏差；且没有任何来自**第二视角**的冗余观测可用于校验或修正。
- 目标不是换一张更好看的帧，而是引入第二视角的几何冗余，产出**一个修正后的红圈锚点**，让红圈在方位与高度两个维度同时更贴近树干实心段中部。

**核心边界（务必先读）**：现有 `UpdateTreeMark` 是「用当前帧姿态把理论树点投影成角度」，若两条射线都由同一个理论树点反算，则两射线必然交于该点，**交会不会产生任何修正量**。因此本次需求的实质是：观测方向必须来自**图像侧量测**（两帧各自在树干 ROI 内定位树干轴心像素 → 反投影成观测射线），或用双帧冗余观测对干心做一致性反算。具体口径见 §6 与 §9-Q1，属于架构师设计前必须确认的前置项。

## 6. 核心需求说明（需求层，不写实现代码）

### 6.1 双帧选帧

- **主帧 A**：直接取现有 `PickFrameUtm(..., refine=true)` 的结果，帧名、距离、方位、仰角、`_pickAng`、`_manualFrameIdx` 一概不变。
- **候选来源**：复用 `PickFrameUtm` 已筛出的合格候选（已通过 `DLO=2.5 / DHI=30` 距离窗、拍摄者扇区 `[45°,125°]` 排除、`off>60°` 排除、整树入框 `spanF ≤ VF43Max+8` 等硬约束），**不新增放宽**。
- **副帧 B 选择准则**（按优先级）：①排除 A；②必须有 Metashape 姿态；③两帧相机中心→树心的水平方位夹角 ≥ 阈值；④在满足条件的帧里取「视角分离度 × 图像质量（遮挡少、清晰、曝光正常）」最优；⑤质量评分应尽量复用 `RefineFrameChoice` 已有的 ROI 质量口径，避免重复读图。
- **视角过近判定**：池内最佳 B 的夹角 < 阈值，或 A/B 相机基线过短 → 记「视角太近」并回退（P0-6）。

### 6.2 交会与新锚点

- **输入**：A/B 帧相机中心（Metashape `X,Y,Z`）、两帧各自对树干的观测方向、`Cal`（水平修正）、`CalV`（垂直修正，是否纳入缓存键需确认，见 §9-Q9）。
- **观测射线来源**：必须来自图像侧量测或双帧冗余一致性反算，**不得由同一理论树点直接反算**（否则无修正量，见 §1 核心边界 / §9-Q1）。
- **输出**：修正后的红圈锚点 `Az / El`，以及置信度、残差、A/B 帧名、状态。该锚点取代 `_autoAzTrunk/_autoElTrunk` 作为自动基准；`ApplyMarkOffset` 仍在其上叠加人工 `dAz/dEl`，绿框/红竖线/黄刻度/红圈/树号整体平移的既有语义不变。
- **居中（高度）策略**：
  - 优先取交会得到 3D 点的 Z；
  - 若仅交出水平位置，高度取「两帧共同可见树干段中点」，建议定义为 `clamp(k·H, zMin, zMax)`，候选 `k≈0.12`、`zMin≈0.8 m`、`zMax = min(0.35H, 2.0 m)`，**具体系数须由离线回放 + 现场样本标定后确定**；
  - 上限 `0.35H` 用于保证不进入分叉/树冠（现注释指出现场树多在 1 m 上下开始分叉）。
- **限幅保护**：修正后锚点相对原自动锚点的角位移超过阈值时，按阈值截断或判为低置信度回退，避免异常交会把手圈甩出树外。

### 6.3 回退与优先级链（自上而下，命中即停）

1. 开关关闭 → 单帧模式（原样，C5）
2. 该树存在 `manual_marks.csv` 记录 → **人工校正优先，跳过双帧**（P0-7 / C4）
3. 副帧不足 / 视角过近 / B 帧姿态缺失 / 当前帧无 Metashape 姿态 → 回退原锚点
4. 交会残差过大 / 置信度 < 阈值 / 缺 trunk.csv / 树高异常 → 回退原锚点
5. 其余 → 使用双帧修正锚点（限幅后）

> 回退锚点统一为：`TrunkMarkH(H)` + `TrunkAxisUtm`（`trunk.csv` 的 Tux/Tuy）；缺该树时退回树心方位 + `TrunkAzBias(2.7°)`。**与现版本完全一致**。

### 6.4 缓存与性能

- 触发点：**仅**「选中树 / 切树 / 精细选帧路径」；`AutoSelectStartupTree` 对 228/439 棵的全量 `refine=false` 调用**不得**触发双帧。
- 缓存键：`树 Id + Cal +（建议含 CalV）+ 数据集标识`；`LoadUtmData`（换数据集）时清空，仿照现有 `_refinedChoices.Clear()`。
- 缓存命中直接复用，不重复加载全景源图；副帧新增读图 ≤2 张/树，ROI 计算沿用现有「缩到 1440×720 再取 ROI」口径。
- 切树/拖准心/改视场引发的重算不得重复跑交会（复用缓存）。

## 8. 验收标准（可量化）

> 所有「基线值」由 QA 在**同一版本、关闭双帧开关**的条件下于三套数据集上先行采集记录；相对指标均以该基线为分母。

### A. 选帧与视角分离

| ID | 标准 |
|---|---|
| A1 | 开启双帧后，三套数据每棵选中树输出的**主帧 A 帧名**与「关闭双帧」时 100% 一致（同一 Cal、同一数据集）；`dist/bearing/elev/_pickAng` 一致 |
| A2 | 判定「交会成功」的样本中，A/B 水平方位夹角 ≥ 阈值（默认 15°）且 A≠B 的比例 = 100%；全库统计「合格双帧覆盖率」并报数（低于 70% 需按 §9-Q5 处理） |
| A3 | 副帧 B 必须自身满足现有全部硬约束（距离窗、拍摄者扇区、偏角、整树入框），且具备 Metashape 姿态，违例数 = 0 |

### B. 定位质量

| ID | 标准 |
|---|---|
| B1 | 三套数据各抽样 ≥30 棵（覆盖近/中距、有无 trunk.csv），以人工目视在两帧上标注的树干轴心为真值，双帧修正后红圈的**方位与仰角绝对误差均值相对单帧基线下降 ≥30%**；且「修正后误差反而增大」的样本占比 ≤10% |
| B2 | 红圈居中：人工目视判读红圈是否落在树干实心段可见范围的 30%~80% 区间，三套数据各 ≥30 棵，命中率 **≥85%**；红圈落到草丛 / 树冠枝杈的样本占比 **≤5%** |
| B3 | 修正量限幅生效：任意样本的红圈角位移不超过配置阈值；因限幅截断或残差过大而回退的样本均带明确状态，无「红圈甩出树外」样本 |
| B4 | 置信度与结果一致：判为「交会成功」的样本残差/基线角均达标；判为回退的样本 100% 使用了原 `TrunkMarkH` 锚点，状态栏原因枚举可核对 |

### C. 兼容与回退

| ID | 标准 |
|---|---|
| C1 | 关闭开关后，9.13 数据的选帧结果、`manual_marks.csv` 内容、红圈像素位置、切图 PNG、识别结果与当前版本**逐项一致（diff 为空）**；三套数据全量遍历无异常、无状态栏报错 |
| C2 | 9.13 数据中 7 棵有人工校正记录（105/106/108/110/111/112/117）的树，无论开关开/关，红圈像素位置与当前版本**完全一致**；「重置为自动」后该树才出现双帧状态；「保存校正」写出的 CSV 格式与现版本一致 |
| C3 | 所有回退场景（§10 边界用例）100% 落到原锚点并输出可枚举原因，无崩溃、无空标注、无卡死 |

### D. 交互

| ID | 标准 |
|---|---|
| D1 | 开关默认开启；切换后无需重载数据即生效；状态栏与 `_lblMarkMode` 在切树、改 Cal、回退、人工跳过时均即时刷新且与实际计算状态一致 |
| D2 | 状态串包含 A/B 帧名、基线角、置信度、状态四要素，抽查 20 棵与后台日志/回放 CSV 一致 |

### E. 性能

| ID | 标准 |
|---|---|
| E1 | `AutoLoadAll + LoadUtmData + AutoSelectStartupTree` 启动耗时相对基线 **≤ +5%**；439 棵数据集启动阶段双帧计算次数 = 0、新增读图张数 = 0（以日志计数核对） |
| E2 | 选中树首次双帧计算 P95 **≤ 300 ms**（或 ≤ 现有精细选帧 P95 + 100 ms，取更严者）；缓存命中重复切树 **≤ 20 ms** 且不新增读图 |
| E3 | 单棵树副帧相关读图 **≤2 张**；`Cal` 改变后结果重算、重载数据后缓存清空、同一树反复切换结果稳定（不抖动） |

## 9. 风险与待确认问题

| # | 问题/风险 | 影响 | 建议处置 / 需谁确认 |
|---|---|---|---|
| **Q1** | **射线来源（最高优先级）**：若两帧观测方向都由同一理论树心 / `trunk.csv` 坐标反算，两射线必交于同一点，交会不会产生修正量，需求落空。需明确采用「图像侧树干轴心量测 → 反投影射线」还是「双帧冗余观测一致性加权反算」 | 决定整个算法可行性与工作量 | **架构师设计前必须由主理人/用户确认口径**。若为前者，需评估近树 ROI 树干检测成功率与失败回退；后者需说明修正量的物理来源 |
| **Q2** | `dataset_runtime_full` 为 Pix4D 局部坐标 + IMU 航向近似；代码注释明确「IMU 航向实测偏差约 90°，不可用」，且两架次合并可能存在坐标系/航向不统一 | 跨架次交会可能系统性偏移，甚至比单帧更差 | 确认该数据集是否已完成坐标与航向统一；未统一前建议**双帧仅在同一架次内选帧**，或对该数据集标记「仅记录、不修正」。需用户提供数据说明 |
| **Q3** | 人工校正语义漂移：`manual_marks.csv` 的 `dAz/dEl` 是「相对自动树干锚点」的偏移；自动锚点定义一旦改变，历史偏移叠加到新基准上会整体错位 | 违反 C4，9.13 的 7 棵历史校正会漂移 | P0 采用「有人工记录即跳过双帧」（P0-7）；若希望历史校正树也享受双帧，需立项 P2-3 版本化迁移并做重标定，**须用户确认** |
| **Q4** | 「居中」与现注释冲突：`TrunkMarkH` 压到 0.42~0.75 m 是当年为躲草丛/分叉刻意设计的；用户现在要求「中部」 | 提得太高会压到分叉口/枝杈，反而被判为错位 | 需现场/离线样本标定树干实心可见段高度范围，再定 `k / zMin / zMax`；建议先以「不得进入 0.35H 以上」做上限保护 |
| **Q5** | 副帧可得性：1292 帧中约 376 帧无 Metashape 姿态；`RefineFrameChoice` 只在最近 1.3 倍距离内取 ≤5 帧，池子小，视角分离度可能天然不足；近树 <4 m 候选更少 | 合格双帧覆盖率过低，功能大部分树实际在回退 | QA 先统计三套数据「合格双帧覆盖率」；偏低时启用 P1-1 扩大候选池或调阈值，**但不得放宽主帧硬约束、不得增加启动读图** |
| **Q6** | 置信度/残差/基线角/限幅阈值的具体数值缺乏依据 | 阈值拍脑袋会导致大量误回退或误接受 | 参考 `outputs\选帧质量回放.csv` 做离线回放标定，参数集中可配（P1-3） |
| **Q7** | 主帧不变 vs 副帧最优冲突：副帧可能来自更远/更偏的帧，若其观测质量差会污染交会 | 修正后反而劣化（对应 B1 的 ≤10% 约束） | 对 B 帧质量设下限，低质量 B 直接判回退；必要时用置信度加权而非等权 |
| **Q8** | ONNX 识别 / 热力图链路耦合：`_cropClean` 是未烤树号的干净切图，红圈与树号位置变化是否影响模型输入 | 识别准确率波动 | 确认切图渲染中心仍由 `RefreshCrop` 的 `cAz=bearing+_markDAz / cEl=elev+_markDEl` 决定；本次不改渲染中心口径，回归时加测识别结果一致性 |
| **Q9** | 缓存键：现有 `_refinedChoices` 键只含 `Cal`；若 `CalV`（垂直修正）参与交会高度，缓存需纳入 | 改 CalV 后结果不刷新 | 架构师确认 `CalV` 是否进入射线反投影；若进入则缓存键包含 `CalV` |
| **Q10** | 视角分离度定义：用「方位夹角」还是「基线长度/距离比」或两者加权；两架次合并数据里同一树可能被重复拍摄，夹角分布未知 | 阈值是否通用 | 由架构师结合 Q2/Q5 的统计确定，PRD 只规定「必须可量化、可配、有阈值」 |

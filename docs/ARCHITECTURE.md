# TreeExtract 系统设计

本文描述当前实现和维护边界，不将启发式判断当作识别真值。用户操作说明见 [桌面使用说明](../desktop-js/README.md)，验证方法见 [开发与发布](DEVELOPMENT.md)。

## 组件与数据流

```text
操作人员
   │
   ▼
Electron Renderer：HTML / CSS / JavaScript
   │  window.treeApp：显式公开的操作
   ▼
preload.js ──受限 IPC──> ipc-registrar.js（调用来源统一校验）
                             │
                             ├─ tree-ipc.js：桥接白名单、文件对话框、切图安全确认
                             ├─ species-ipc.js：树种、密钥、预览与逐次上传同意
                             ├─ merge-ipc.js：采集数据检查、输出位置和独立打包进程
                             ├─ session-coordinator.js：互斥与预览失效
                             ▼
                    backend.js / json-line-decoder.js（本地进程客户端）
                             │  本地子进程，stdin / stdout JSON Lines
                             ▼
        DesktopBridgeProgram / DesktopProtocol / BackendSession（.NET 10）
                    ├─ 数据与帧：位姿、树心、树干轴心、ZIP 全景
                    ├─ DatasetLoader：只读准备与校验，再由会话接管数据和 ZIP 句柄
                    ├─ ManualMarkRepository：校正文件解析、冲突检测、原子保存与备份
                    ├─ 单帧定位与投影 / 双帧候选、交会和回退
                    ├─ 照片生成、人工校正、对照表导出
                    ├─ ONNX Runtime 本地树种识别和人体/头部风险检测
                    └─ 切图摘要确认与原子导出
```

界面和算法进程有各自的生命周期。`main.js` 限制 IPC 来源和允许的方法，页面不直接获得 Node.js、文件系统或原始 IPC。后端使用 Windows 下的 `System.Drawing.Common` 处理图片，但不是 WinForms UI。常规功能离线；可选云端复核只在用户逐次确认后发起，程序没有自动更新系统。

`partial` 文件按职责拆分同一类型，不改变公开行为；调整时需要同时检查上下文、候选、计算和回放对应的测试。

当前 `BackendSession` 仍通过多个 `partial` 文件共享可变会话字段，`AppPaths` 仍承担进程级配置；这些不是已完全解耦的领域服务，也不支持把同一后端实例当作多个互相隔离的会话。后续若迁移到显式会话配置与独立领域对象，应先固定协议、现场数据回归和保存行为，再分步迁移，不能仅凭移动文件宣称算法或并发安全得到证明。

## 会话和展示职责

- 页面状态由 `app.js` 编排，后端会话仍是图片、定位和保存结果的权威来源。树列表以树数组引用、搜索词和当前树序号判断是否需要重绘；帧或视角单独改变时复用现有 DOM。**调用方更新树集合必须替换数组，不能原地修改**，否则缓存无法感知变更。搜索仍只匹配树号。
- 所有公开 IPC 均由统一注册器先验证窗口、主框架和页面地址；再按树木或树种职责分发。预加载通道与注册表、桥接白名单与后端分发表都有契约测试。不能将仅供内部验收的快照方法直接暴露到页面。
- 预览开始时记录代次；切树、修改视图、取消预览或启动独占操作会使在途预览失效，迟到快照不能重新成为上传凭据。上传仍必须经实际预览、用户勾选、原生对话框和上传前快照复核。
- 树种确认、联合识别及密钥增删在同一会话内互斥；独占期间拒绝会改变会话的桥接调用，读取状态和图片仍可用。无论成功、取消或异常，锁都会释放。该协调器是应用内部一致性机制，**不是抵御恶意本机进程的安全边界**。
- `DesktopProtocol` 不接触控制台或图像算法，只把一行请求转换为分发调用，再编码一行响应；`DesktopBridgeProgram` 负责 UTF-8、顺序读写及会话生命周期。协议测试覆盖嵌套参数、错误、请求 ID 与序列化失败，完整桥接测试仍需启动真实进程。
- 数据切换采用“准备 → 提交”：`DatasetLoader` 先读取树心、全景索引、第一路 IMU、相机位姿、校正及可选配套表，检查重复树号及准备前后文件大小和修改时间；只有准备成功才交出 ZIP 句柄并更新当前会话。输入无效时保留旧会话并在界面提示未切换。文件戳不是内容哈希，准备完成后的极端并发修改和提交/渲染时的意外异常不构成完整事务回滚保证。

## 请求协议与故障

前端发送一行 `{"id":1,"method":"state","params":{}}`，后端按顺序处理并以 `id`、`ok`、`result`、`error` 返回一行 JSON。`BridgeClient` 按 ID 对应请求，允许分块和多行；一行限制为 64 × 1024 × 1024 个 JavaScript 字符。畸形响应或超长响应使协议会话失效并终止该进程；管道错误会拒绝所有未完成请求。等待进程 `close` 后处理退出，避免最后的合法响应丢失。

请求超时只停止等待，**不表示后端操作已经取消**；迟到响应会被丢弃，重试涉及保存或导出的操作前应先确认实际状态。不能把超时自动当作执行失败，更不能为提高响应速度无条件杀进程而丢失未保存的校正。启动验证显式处理 Windows PowerShell 5.1 的 UTF-8 BOM 兼容问题。

预期的业务错误使用 `UserFacingException` 保留操作上下文；未标记的内部异常仍沿用最内层错误。不能将未经审查的内部错误直接包装成可公开的提示。

## 选帧、标注与状态

- 默认“优质近帧”按候选质量综合选择，不是全局最近。不同树在同一数据会话内的已展示主帧会登记，自动优质模式排除其他树的已登记帧；没有独立可用帧则清空旧帧并提示。手动选帧与严格最近允许显式共享，但登记所有使用者并提示；自动优质模式不会复用共享帧。数据重载时清空记录，结果可能随选树顺序而变化。
- 在候选距离与原有视场、经验风险约束内，优先寻找与 8 米内邻树轴心夹角超过 5° 的视角。候选分离视角和原近帧各最多读取 5 张照片，若分离视角的图像质量分比原近帧低超过 2，则保留原近帧并显示邻树歧义提示，避免仅为不同角度而选出明显无法辨认的图。8 米、5°、质量分差 2 均为待现场核验的启发式，不保证没有遮挡、图片不是同一实体树或识别准确；两张不同文件也可能内容相似。保留已有人工校正并提示用户换视角后检查。
- “水平最近”只在具有完整位姿且存在于全景包的帧中，计算相机到树干轴心（缺失时树心）的水平距离；若和另一棵树的帧重合，不换成次近帧而是明确提示。对照表沿用自己的树心对照规则，两者不是同一个口径。
- 手动切帧或定位当前帧最近树会固定当前树的帧；重选当前树保留固定帧，切换到另一棵树或加载另一套数据恢复自动选择。没有有效位姿时允许浏览全景，但不得沿用上一帧角度伪造切图。
- 全景 ZIP 内的帧按时间排序；重复帧名、无效时间、空文件或展开后超过 128 MiB 的单帧会被拒绝，实际读取也限制字节数，解码图像不超过一亿像素。IMU 读取在第一次时间回跳处停止，与对照表的第一路约定一致，航向插值按圆周最短路径进行。对于已经把不同镜头槽位按时间混排、却不带镜头标识的文件，程序不能自动识别各路来源。
- 双帧以 A 为主帧，最多尝试三张 B：对候选进行观测、轴心几何、邻树歧义、共同可见段和纹理检查；可投影时以 A 的实际 4:3 画面内候选段中点确定目标高度，并要求 B 覆盖。判断基于启发式，候选本身也可能选错；通过不等于人工确认。
- 界面状态包括未就绪、未执行、关闭、人工优先、通过和单帧回退。回退高度是经验估计；人工标记优先且只有用户保存才写入数据目录。新增的连续边缘候选默认关闭，只有进程启动时显式设置 `TREEEXTRACT_EXPERIMENT_EDGE_CANDIDATE=1` 才启用；详见[实验记录](research/双帧边缘连续候选实验-20261113.md)。
- 4:3 照片与实际切图分别以本地模型检测人体/头部，阳性时界面默认隐藏相应图片，明确选择后仅显示该张。模型未检出或不可用不能说明画面安全；没有头皮专用检测，全景预览也未检测。
- 双帧缓存的键包含树、数据集标识、主帧、校正和视图投影参数；树心文件路径、大小、时间戳构成数据集标识的一部分。这不是文件内容哈希，也不是对所有输入未变化的密码学证明；更换数据、校正和视图参数必须按现有失效规则处理。

## 数据生命周期与隐私

数据目录的树心、位姿、树干轴心和选定的全景 ZIP 是输入。人工校正保存到对应树心目录的 `manual_marks.csv`；切图和表格由用户选择目标路径。后端运行目录可能写入 `error.log` 和 `outputs/双帧交会回放.csv`，回放在特定状态切换时会重写；单文件 EXE 的运行目录是解压临时目录，不是可靠的长期存储位置。分享日志、回放或截图前应检查真实路径、地点、树木和人物等敏感信息。

手动校正必须完整、无重复树号且数值有限才能加载；错误不会被静默跳过。保存前比较加载时的文件内容摘要，若文件在外部发生变化则拒绝覆盖并保留内存中的未保存状态。成功替换时生成同目录、唯一命名的旧文件备份；这些备份不会自动清理。摘要比较与原子替换可降低意外冲突和数据丢失风险，但不是针对恶意本机进程的锁或多用户事务。

合并检查只读取 JPEG 文件头和尺寸，不证明每张照片均可完整解码；坐标参数一致也不证明点云同源或已经精确配准。合并输出保留原始完整位姿，不为缺失记录编造数据；没有已配准树心时只能生成影像和位姿，不能直接加载树列表。

树种的云端视觉只接收当前干净切图和分级类别表，后续文字复核接收本地与视觉结果，不主动发送全景、路径或坐标。联网前需人工核查和原生对话框逐次确认，图片可能含人物或文字，无法保证脱敏；API 密钥在当前 Windows 用户的应用数据目录加密保存，不打包或写入日志。当前用户下的其他程序仍可能访问该密文及解密能力。人工确认独立保存在应用用户数据目录，与源树木文件和对照表分离；切图摘要用于防止对旧图的确认误用于新图。详细限制见[树种复核与全景交互](guides/树种复核与全景交互.md)。

`photo.snapshot` 为离线 QA 按需原子返回干净图片、标记图片、身份和未钳制的红圈坐标；不向页面公开该接口。`dual.evidence` 仅在当前确有双帧成功且能核对原始分析缩图时，按需返回实际获胜的 A/B 观测及无损图证；无证据时不以估计结果冒充，接口细节见[双帧图证](guides/双帧图证接口-20261113.md)。图证可能含有现场人员，应仅在本地受控保存。

`crop.inspect` 对实际干净切图检测并计算待输出 PNG 摘要，`crop.save` 要求用户确认和摘要匹配，禁止覆盖输入路径或重解析点，并以同目录暂存、原子替换与备份降低误覆盖风险。该 JSON 通道不是对恶意本机调用者的安全边界。

自动化真实数据测试复制小文件并将标注、回放及导出写到临时位置，只读取原始 ZIP；测试截图存到 `desktop-js/test-artifacts`。具体前置条件和限制见开发文档。重建运行时会交换目录；`-KeepBackup` 可保留旧运行时，任何清理操作都应先人工确认文件归属及备份。

# 真实影像独立标注与验收

## 目的和不可替代的前提

这个工具将同一时刻的无标记 4:3 照片、有标记照片和算法输出采集成隔离证据；再用独立人工标注测量画面红圈位置、双帧候选及人体/头皮判断。**空标注不等于通过，也不能计算定位准确率。** 要确认“正确的树”，标注人员还需可靠的现场树号、参考图或其他独立资料；只看软件预测的红圈、树号或相机距离，无法获得独立真值。

已有三套数据最近相机的几何穷举回归仍由 `tests/QA-nearest-all.js` 负责。它验证的是在有完整位姿且 ZIP 中存在的帧内计算水平最近，不能证明目标可见或红圈正确。本工具评估的是独立标注后的图像效果，两个结论不可互换。

## 1. 采集待验收图像

在项目根目录，使用已构建、包含 `photo.snapshot` 接口的隔离候选桥接程序。下面以默认数据第 120～170 个 **UI 序号**为例；树号可能不等于序号。

```powershell
node .\tests\qa-collect-annotations.js --dataset D1 --data ..\tree --zip ..\tree\Camera4.zip --bridge .\desktop-js\runtime\TreeExtractorBridge.exe --from-index 120 --to-index 170 --require-model true --require-evidence true
```

对于第二、第三套数据，把 `--dataset`、`--data`、`--zip` 和序号范围改成对应数据；每套必须是同一批次的树心、位姿和照片。`--dataset` 应使用稳定且互不重复的标识，只能包含英文字母、数字、下划线、点或连字符。候选桥接程序应显式指向实际待测版本；源码构建不会自动更新旧 EXE 或旧运行时。

采集器复制六个小数据文件和桥接运行时到新建的系统临时工作目录，在该副本写入日志、回放和其他运行数据，只读取原 ZIP。采集前后对六个原文件计算 SHA-256；大型 ZIP 检查大小和修改时间，**不是全文件哈希**。程序在屏幕输出证据包和隔离工作目录，即使失败也不删除临时目录；两者都可能包含位置、图像、日志和人工标注，请按敏感数据保管，工具不上传影像。`--require-model true` 要求每张照片都有可信的人体/头部模型结果；不可用或数据不一致时返回退出码 `2`，但这不代表模型零漏检。发现字段矛盾或模型哈希不一致时，即使未加该选项也会返回 `2`。

证据包结构：

```text
labels/
  clean/000120-clean.jpg      # 无树号、红圈和预测线；供盲标
  labels-template.json        # 真值全部为 null，按需另存填写
evidence/
  marked/000120-marked.jpg    # 已绘制模型输出；盲标阶段不要给标注者看
  pairs/000069-panoA.png      # 成功配对的 A 原始分析图（仅成功且可取证时存在）
  pairs/000069-panoAMarked.png # A 实际胜出候选标记图
  pairs/000069-panoB.png      # B 原始分析图
  pairs/000069-panoBMarked.png # B 实际胜出候选标记图
  predictions.json            # 程序输出、图片哈希、位姿帧身份、算法状态
```

照片和坐标来自同一个串行 `photo.snapshot` 请求；采集器还核对选择结果的树号、帧名和 UI 序号，校验两张图画幅一致、图像为 4:3。`photoMarkNormalized` 不存在或画面不存在时记为 `null`，不会猜测或钳制画外坐标。图片的 SHA-256 绑定实际 JPEG 字节；JPEG 画幅通过 SOF 标头核验，这不是完整 JPEG 解码检验。

默认保留数据副本中的现有人工校正，结果可能处于 `manual` 状态；评估报告单列人工和自动标记误差，不应把人工校正当作算法性能。照片风险的经验几何提示不是人像检测。只有 `photo.snapshot.peopleDetection` 明确报告完整且字段有效的模型结果，并且上报模型 SHA-256 与隔离运行时中实际模型文件一致时，才记录 person / head 的检出或未检出；模型不可用、缺字段、状态矛盾或哈希不匹配均记为 `unknown`。接口中的 `personDetected` 已聚合为 **身体或头部任一检出**；当前接口没有单独暴露原始身体类别。若出现 `headDetected=true` 却 `personDetected=false` 的矛盾，采集器全部记为未知。未检出是模型输出，并不证明画面无人。头部检测并不等同于头皮检测；现有接口不提供头皮识别，因此 scalp 仍记为 `unknown`，不能计算头皮检出率。

## 2. 独立填写标签

### 可视化离线标注

在可信的 Windows 本机用 Chrome 或 Edge 打开 `tests/annotation/index.html`，选择证据包的 `labels/labels-template.json` 和 `labels/clean` 文件夹。页面只读取用户选中的本地文件，不请求网络、不加载预测文件；每次显示和下载前会验证已标注照片的原始 JPEG SHA-256 与实际解码宽高。填写标注者代号后，在独立确认的可见树干中点单击，或输入归一化坐标，并选择人体、头部和头皮的“是 / 否 / 未知”。无法确认目标树时保持未知，不必强行点坐标。

使用页面上方“校验并下载标注 JSON”导出，手动确认下载文件已保存，再复制到证据包 `labels` 目录并命名为 `labels.json`。页面不会自动覆盖输入文件；浏览器若取消或阻止下载，请保留页面并重试。标注过程未上传数据，但浏览器下载目录和本机临时证据仍需妥善管理。

### 字段口径

也可以把 `labels-template.json` 另存为新文件手工填写，使用干净照片以及外部、独立的树号参考。不要把 `evidence` 文件夹交给盲标人员；保留树号、照片 SHA-256、宽高和帧名，不要修改。对每项填写：

| 字段 | 允许值与含义 |
| --- | --- |
| `reviewer` | 标注者的非空代号，避免在结果中使用真实姓名。 |
| `reviewMethod` | `blind`：未看到预测；`prediction_visible`：看过红圈或预测。系统仅能校验图片是否干净，不能证明实际盲法过程，须靠工作流程保证。 |
| `targetVisible` | `true` / `false` / `null`；只能在有独立树号依据时判断，不能确定则填 `null`。 |
| `trunkCenter` | 可见且可确定目标时的 `{ "x": 0.5, "y": 0.4 }`，否则 `null`。标的是**可见树干部分的中点**，不是树冠或整棵树的中点。 |
| `personVisible` | 人体任何部分是否可见，`true` / `false` / `null`；不能确定就留空。 |
| `headVisible` | 头部是否可见，`true` / `false` / `null`；不能确定就留空。 |
| `scalpVisible` | 头皮/头顶是否可见，`true` / `false` / `null`；不能确定就留空。和人体分别标注。 |
| `pair` | 默认 `null`。仅在确有 A/B 两帧实际胜出候选的图证且人工完成复核后填写，见下文。 |

坐标使用图片左上角为原点：`x = 水平像素坐标 / 图片宽度`，`y = 垂直像素坐标 / 图片高度`。参考点应在 `[0, 1]`；算法预测点可在画外，工具不钳位。误差计算为 `sqrt(((x预测-x真值)×宽度)^2 + ((y预测-y真值)×高度)^2)`，单位是该照片实际像素。真值应注明不确定样本；被遮挡或无法确认树号不能硬填坐标。

### 双帧人工图证

先完成主帧盲标、下载标注并记录文件哈希，然后在可信本机用 Chrome / Edge 打开 `tests/annotation/pair.html`。依次选择前一步下载的标注 JSON、同一采集包的 `evidence/predictions.json` 和 `evidence/pairs` 文件夹。此页会显示算法实际采纳的 A/B 候选，因此**不是盲标页面**；未经人体遮挡处理的全景图证可能包含人物，请勿公开传播。

复核页面检查树号、帧名、尝试次数、四张 PNG 的文件 SHA-256 和解码尺寸。两个候选线框都可辨认且有独立树号依据时，填写复核者代号，分别判断“同一棵树”和“两个候选都是目标树”，并勾选已核对候选线框。无法确定就保持未知，不需要强行回答。下载 `labels-with-pairs.json` 后，用它作为下节评估的标注输入；主帧盲标者和方法不会被双帧复核者覆盖。

图证仅在某次实际双帧候选通过且来源核对成功时提供。四张图是 A/B 分析全景的原图和对应候选线框图，不是 4:3 红圈图，也不能证明该候选就是正确树干。采集器和评估器会独立解码无损 PNG，并以 `sha256-wh32le-topdown-bgra32-v1` 复算宽高加紧密 BGRA 原始像素哈希；两侧帧、胜出尝试、线框附近像素变化或哈希不符则拒绝图证。`--require-evidence true` 可让“有成功配对但无法取证”返回退出码 2；**没有成功配对时不会凭空生成图证**，同树仍是未评估。

系统无法自动证明人工复核的判断正确，也无法证明标注者事先没有见过预测。若标注者在确定主帧中点之前已看过预测或候选，应将该条的主帧 `reviewMethod` 标为 `prediction_visible`。详细图证契约见 [双帧图证接口](双帧图证接口-20261113.md)。

## 3. 生成评估报告

在项目根目录，将 `$run` 改成采集器实际输出的证据包完整路径，使用另存填写的 `labels.json`：

```powershell
$run = 'C:\path\to\treeextract-qa-collection'
node .\tests\qa-evaluate-annotations.js --predictions "$run\evidence\predictions.json" --labels "$run\labels\labels.json" --output "$run\evaluation.json"
```

输出只创建新文件，不覆盖既有报告或输入。`labels-template.json` 也可直接用于检查空标注行为：红圈误差、人和头皮指标会显示 `not_evaluated` / `null`，而不是 0 误差或 100% 准确率。标注文件若与图片哈希、画幅、树号、帧名、B 帧或图证不一致，评估直接报错。报告保存预测、标注和评估脚本的 SHA-256；这些文件目前并未签名，哈希只能辅助核对，不能单独证明标注过程真实或文件未被有意替换。

报告分别给出：

- 可见、不可见、未知目标数量；盲标和见过预测的样本数量；有真值但缺预测及有目标但缺真值坐标数量。
- 红圈像素误差的均值、中位数、P90、P95，分别统计全部、盲标、盲标且自动、盲标且双帧成功、见过预测、自动、人工、双帧成功及回退样本。它们只基于已标注且有坐标的样本；不得忽略缺失及不可见样本。
- 双帧 `success` 与 `fallback` 数量和程序通过率；另列成功样本中复核了同树 / 目标树的分母、未复核数及复核结果。**程序通过率不是正确率**，仅按已复核子集计算的比例也不能代表未复核样本。
- 人体、头部和头皮分别列出全部标签及盲标子集的 TP、FP、TN、FN、真实标签数量、预测为 `unknown` 数量和已分类覆盖率。敏感度/特异度仅针对已给出明确预测的样本；另给出将有真值但模型未判定的样本分别按最坏、最好情况计算的上下界，这不是统计置信区间。零分母显示 `null`。

若要让证据不足的自动化步骤失败，可额外设置所需的最少已评估样本：

```powershell
node .\tests\qa-evaluate-annotations.js --predictions "$run\evidence\predictions.json" --labels "$run\labels\labels.json" --output "$run\gated-evaluation.json" --min-blind-points 51 --min-pairs 10 --min-person 20 --min-head 20 --min-scalp 20
```

数量要求应由项目在验收前确定，而不是事后挑选；`--min-blind-points` 只统计盲标且算法自动生成的标记，不计人工校正；`--min-person` / `--min-head` / `--min-scalp` 只计盲标且模型有明确预测的样本；`--min-pairs` 同时要求同树和目标树两项均有足够复核。未达到任一最小值返回退出码 `2`，但仍生成报告供排查。**这些选项只约束证据数量，不是质量阈值，也不意味着算法已安全或满足精度要求。** 当前尚无经用户认可的误差阈值、标注真值或人体/头皮误检漏检标准。

## 4. 工具自身测试

```powershell
node --test .\tests\qa-annotations.test.js
```

测试用合成纯色图片，不是现场数据。覆盖哈希/画幅、无标注、树号/帧名错配、重复标注、盲标约束、B 帧图证、人体和头皮未判定、画外红圈、证据不足退出码及报告不覆盖。合成工具测试通过只说明评估流程按约定处理这些输入，不能代替真实标注和现场视觉验证。

标注页面的无浏览器逻辑和实际浏览器测试：

```powershell
node --test .\tests\qa-annotation-core.test.js
node --test .\tests\qa-annotation-ui.test.js
node --test .\tests\qa-png-evidence.test.js .\tests\qa-dual-evidence-validation.test.js .\tests\qa-pair-ui.test.js
```

浏览器测试需要本地 Chrome / Edge 及项目已安装的 Playwright；缺少浏览器时报错而不是静默跳过。测试只使用合成纯色图片，并确认没有发出 HTTP(S) 请求。

D2 中可复现双帧成功的树 `treeId=210` 可用于真实桥接图证回归：

```powershell
node .\tests\qa-dual-evidence.js --data ..\dataset_runtime\data --zip ..\dataset_runtime\data\Camera4.zip --bridge .\desktop-js\runtime\TreeExtractorBridge.exe
```

该脚本按真实 `treeId` 查找 UI 序号；仅在隔离副本中移除该树已有的人工校正以测试自动分支，保留其他记录，并核对原始六个文件的 SHA-256 未变。它验证 A/B 原始像素哈希、标记位置、重复调用、切树切帧、同名 B 内容改变以及只保留 A 后重载的失效行为。篡改和缩小 ZIP 均仅发生于临时副本；源 ZIP 只读，前后仅检查大小和时间。该单个 success 样本不是独立人工真值，也不代表其他照片的正确率。

测试实际切图导出的安全状态和失败路径，需显式指定数据与候选桥接程序：

```powershell
node .\tests\qa-crop-safety.js --data ..\tree --zip ..\tree\Camera4.zip --bridge .\desktop-js\runtime\TreeExtractorBridge.exe
```

脚本分别在有、无人体检测模型的隔离副本中运行，检查当前帧最近树的风险提示、图片摘要绑定、风险确认、切图变化后旧确认失效、已有切图备份及保护输入文件。它在临时目录留存副本与测试输出，仅检查原 ZIP 大小和时间不变；与其他合成回归一样，不能证明模型没有漏检。

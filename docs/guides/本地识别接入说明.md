# 本地树种识别（ONNX）接入说明

## 做了什么

树木识别现在**完全离线**，不再调用在线大模型：

- 模型：YOLOv8s-cls · 18 个树种 · 输入 384×384
- 推理：ONNX Runtime，CPU
- 速度：约 280–350 ms/张（含多视角一致性检查）
- 不联网、不需要 API Key、结果确定

界面上「树木识别（本地）」面板只有一个按钮：

| 按钮 | 返回 |
|---|---|
| **本地识别（18 树种）** | 树种 + 置信度 + top3 + 可靠/存疑 |

识别完成后，切图下方会显示注意力热力图（遮挡敏感性，约 1 秒）。

## 文件

```
TreeExtractor.exe                     主程序
models\tree_cls.onnx                  树种模型（19.5MB）
Microsoft.ML.OnnxRuntime.dll          ONNX Runtime 托管库
onnxruntime.dll                       原生库（18.4MB）
System.Memory.dll / System.Buffers.dll / System.Runtime.CompilerServices.Unsafe.dll
_deps\ort\                            上面这些 DLL 的源目录（build.ps1 从这里拷贝）
src\TreeClassifier.cs                 识别模块
```

**发布时这几个 DLL 和 models 目录必须跟着 exe 一起走**，否则「本地识别」会报找不到模型。

## 18 个树种

柏类、广玉兰、桂花、红叶李、夹竹桃、榉树、柳杉、柳树、栾树、落羽杉、木芙蓉、朴树、青桐、珊瑚、无患子、香樟、悬铃木、银杏

> 注意：**棕榈树、雪松不在这个模型的 18 类里**。遇到这两类需要扩展模型/补训练数据，或人工确认；程序已不再提供在线识别兜底。

## 命令行自检

```powershell
TreeExtractor.exe --selftest 图片路径 [输出txt]
```

会打印树种、top3、一致性、可靠判定和耗时，用于排查模型是否正常加载。

## 关键实现细节

1. **预处理必须与训练一致**：短边缩放到 384（双线性）→ 中心裁剪 384×384 → RGB /255。
   **不做 ImageNet 归一化**（ultralytics 分类模型训练时就没做，加了会全错）。
2. **类别顺序**固定在 `TreeClassifier.Slugs`，与模型 `names` 一一对应，改动会导致全部错位。
3. **类别校准**：栾树的 logit 减 1.0（`TreeClassifier.Bias`），抑制它把无患子/银杏吸走。
   来源是在验证集上按宏平均扫描选出，测试集上栾树精确率 78%→92%。
4. **可靠性判定**：置信度 ≥0.5 且 5 个裁剪中 ≥4 个与整图结论一致。
   置信度 ≥0.85 时跳过一致性检查以省时间。
5. 模型输出已带 softmax（`output0` 的 18 个值直接求和为 1），不需要再 softmax。

## 性能

| 场景 | 耗时 |
|---|---|
| 首次调用（含加载模型） | ~300 ms |
| 后续单张（置信度高，跳过一致性） | ~60 ms |
| 后续单张（置信度低，跑 5 个裁剪） | ~250 ms |

## 如果要更新模型

1. 在 `E:\树木识别\yolo` 里训练，导出：
   ```python
   from ultralytics import YOLO
   YOLO("tree_cls_best.pt").export(format="onnx", imgsz=384, simplify=True, opset=12)
   ```
2. 覆盖 `models\tree_cls.onnx`
3. 如果类别有增减，同步改 `TreeClassifier.Slugs` / `Names` / `Bias`
4. 重新 `build.ps1`

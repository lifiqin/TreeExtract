# 本地发布清单

`desktop-js/scripts/release-manifest.js` 为指定的 Windows EXE 和当前工作区生成本地内容清单。它**不构建或修改 EXE**，不读取影像数据集、人工标注、日志、导出文件或 `runtime`，也不会上传内容。

在项目根目录的 PowerShell 中执行，输出文件必须是尚不存在的 `.json` 文件：

```powershell
$output = Join-Path $env:TEMP ('treeextract-release-' + [guid]::NewGuid().ToString('N') + '.json')
node .\desktop-js\scripts\release-manifest.js --artifact .\desktop-js\release-net10\TreeExtract-Portable.exe --output $output
```

清单记录：

- 固定的工程配置、`.NET` / npm 锁文件、119 项树种目录、ONNX Runtime 依赖、两个模型及相应许可文件；
- 明确限定的源代码目录及文件扩展名，包括 C#、JavaScript、HTML、CSS、PowerShell 和现有测试源码；`tests/annotation` 下六个盲标及双帧复核核心文件为必需项，其他同目录源码按扩展名收集，标注 JSON、测试图片和生成目录不纳入；
- 指定 EXE 的 SHA-256 和字节数，**不记录 EXE 的原始路径或文件名**；
- 本地 Node.js、npm、.NET 10 SDK 版本，以及依赖锁中记录的 Electron 等工具版本。锁文件版本不代表实际制品一定使用了这些版本。

清单中的源码路径始终是项目内相对路径，不记录工作区或输出目录的绝对路径。生成器检查输入路径和输出父目录，不接受符号链接或 Windows junction；缺少必需文件、源码组为空、锁文件与声明的工具版本不一致、输入在读取期间发生变化或输出已经存在时会报错。这些本地检查不能防范拥有同一账户权限的恶意进程并发替换路径。输出使用独占创建，若中途发生磁盘错误，可能留有不完整的新文件，检查后应选择新的输出路径重试。

**这是内容快照，不是构建证明、制品来源证明、软件物料清单或数字签名验证。** 即使清单中同时记录源码和 EXE 的哈希，也不能证明该 EXE 由这些源码构建；不能据此声称软件已签名、安全或通过现场准确率验收。正式发布需另行保存隔离构建记录、测试报告及可信证书验证结果。

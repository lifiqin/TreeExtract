# 本地人体与头部风险检测

## 模型来源和适用范围

本功能使用本地 `models/person_head.onnx`：PINTO0309 发布的 `yolov9_t_wholebody34_0100_1x3x640x640.onnx`，8,192,670 字节，SHA-256 为 `7dd9b514426b33423ffbc4e22fb6127f2145686441f2c398170585363c009575`。每个后端会话首次加载前会校验该摘要；缺失、损坏、加载失败或推理失败都返回 `unavailable`，不能当成检测阴性。模型文件和许可声明随程序发布，推理在本机 CPU 上运行，**不上传照片**。

- [发布与预处理说明](https://github.com/PINTO0309/High-Angle_Robust_Fast_FaceAlignment)：发布者描述该模型及 34 类输出。
- [发布锁文件](https://raw.githubusercontent.com/PINTO0309/High-Angle_Robust_Fast_FaceAlignment/main/demo/web/models.lock.json)：可核对文件名、大小和 SHA-256。
- [原始类别配置](https://raw.githubusercontent.com/PINTO0309/YOLO/wholebody/yolo/config/dataset/wholebody34.yaml)：类别 0 为 `body`，类别 7 为 `head`。
- [发布者的权重许可说明](https://github.com/PINTO0309/High-Angle_Robust_Fast_FaceAlignment/issues/2)与[原始项目 MIT 许可证](https://github.com/PINTO0309/YOLO/blob/wholebody/LICENSE)；随包提供 `PERSON_HEAD_LICENSE.txt`。

## 结果与边界

模型输入为原始 4:3 照片或独立切图，直接缩放到 640×640，RGB / 255；对 body 和 head 类别按 0.35 分数阈值检测并分别执行 NMS。该分数不是概率校准后的准确率。4:3 与单木切图视场不同，必须分别检测；同一帧和相同投影参数的检测结果可复用，切换数据、帧或取景参数后重新计算。

`photo.snapshot.peopleDetection` 与 `images.cropPeopleDetection` 返回 `status`、`personDetected`、`headDetected`、`scalpDetected`、`model`、`modelSha256`、`scoreThreshold`、`error`。`status=unavailable` 时三个检测字段均为 `null`；`complete` 时，即使只识别出头部，`personDetected` 也为 `true`。`scalpDetected` 始终为 `null`：这是人体/头部检测，**不是头皮识别或图像隐私认证**。

模型阴性只意味着本次推理没有输出超过阈值的相关候选。部分头皮、头顶、肢体、遮挡、畸变、强光、小目标及超出画幅的情况都可能漏检；背景和标注也可能误报。人体风险先验仍只是一种几何估计。全景预览没有经过人体检测，不能推断全景没有人物。

界面分别使用 4:3 照片和切图各自的检测结果；对于模型阳性的图片默认隐藏，并允许用户对当前图片单独选择“仍要查看”。确认只对应同一图片内容，切换到不同图片不会继承。未检出或检测不可用时，界面仍提示不能排除人体或头皮；由于模型可能漏检和误报，该遮挡机制并不能保证看不到头皮，也不覆盖全景预览。

## 离线测试与真实样本初筛

`tests/run_person_head_tests.ps1` 包含输出格式、类别与 NMS、非有限值、缺失/篡改模型、重复推理、资源释放、会话结构化状态和切图写入安全测试。公开领域 NASA 宇航员正面照片用作正例：本机试验中 body 得分 0.947、head 得分 0.977；灰色空图未检出。这些只是功能烟雾测试，不是业务场景准确率。

同一公开照片经人工裁成头顶部的一小块毛发（原图 `x=190, y=16, width=60, height=20`）后，本机测试 person 和 head 均未检出。这不是头皮真值集，但提供了明确反例：画面可能含有人体局部而模型给出阴性。

默认 D1 的 120～170 号共 51 张**已有树号和红圈的 4:3 图片**在本机离线扫描约 2.5 秒，其中 134 号检出 head，152、153 号检出 body；人工快速查看，候选位于枝叶/红圈附近，疑似误报。其余图片未检出并不证明没有头皮。该扫描与产品对未烤标注原图的推理输入并不完全相同，也没有人工真值，无法统计现场召回率或漏检率。需要对真实照片进行独立人工标注，并覆盖只有头顶、图像边缘、背面和遮挡等困难样本，再评价实际效果。

测试可在项目根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\run_person_head_tests.ps1
```

默认模式允许权限不足时跳过文件符号链接集成测试，但会在摘要输出 `PASS WITH SKIPS`、跳过数量和原因；这不表示所有测试均已覆盖。需要强制验证文件符号链接的环境应运行以下严格模式；如果系统或账号不能创建符号链接，测试将以非零状态失败：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\run_person_head_tests.ps1 -RequireSymlink
```

真实图片扫描需显式提供本地图片目录：

```powershell
$ImageDirectory = 'C:\path\to\images'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\run_person_head_tests.ps1 --scan $ImageDirectory
```

不要将包含真实人像、位置、树木或文件路径的测试数据和日志上传至公共服务。

## 切图导出保护

保存前会针对实际切图检查，界面要求人工确认；**即使模型未检出也必须确认**。确认绑定当时输出 PNG 的 SHA-256，之后若切图改变，后端拒绝使用旧确认保存。模型不可用或检测到疑似人体时也不能静默保存。

导出只接受 `.png`，拒绝选择当前输入/ZIP/人工标注文件，以及带重解析点的目标或父目录。程序在目标同目录创建唯一暂存文件、写完并 `Flush(true)`：旧文件存在时以系统的 `File.Replace` 替换并保留旧文件备份；新文件若在提交前被其他程序创建，则保存失败且不覆盖对方文件。备份路径随保存结果返回；失败时的暂存或备份路径会显示在错误信息中，请在确认归属后自行处理。

原子替换和持久性还取决于目标文件系统；网络盘和异常断电场景不能假设与本机 NTFS 等同。JSON 桥接协议运行在本机，用户或同权限程序可以自行发送伪造的“已确认”请求，因此该机制防止正常界面中的误操作，不是抵御恶意本机用户的安全边界，也不保证模型漏检时自动保护隐私。

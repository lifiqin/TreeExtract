# .NET 10 迁移与 QA 记录

## 迁移范围

- 无窗口 C# 后端从 .NET Framework 4.x 迁移到 `net10.0-windows`；本次构建使用 SDK `10.0.404`、自包含运行时 `10.0.15`，目标为 Windows x64。Electron / JavaScript 界面和 JSON 行协议保留。
- 使用 `System.Text.Json` 替换旧的 `JavaScriptSerializer`；图像处理使用 `System.Drawing.Common 10.0.15`。ONNX Runtime 仍为 `1.31.1`，模型和选帧、双帧算法判据未改。
- 发布目录包含 .NET 运行时；外层 Electron 便携 EXE 不包含用户数据、人工标注、配置或日志。ONNX 原生库仍依赖 Windows 的 Microsoft Visual C++ 运行库。
- 回归测试项目也迁移到 .NET 10，避免只用旧版 `csc.exe` 验证新运行时。

## 独立 QA

QA subagent 把新旧后端及数据元文件复制到带空格的临时目录运行；原全景 ZIP 只读，人工标注只写隔离副本。三套数据分别抽取：

| 数据集 | 树数 | 有完整位姿的全景帧 / 全部帧 | 抽样树序号 |
| --- | ---: | ---: | --- |
| D1 | 228 | 916 / 1292 | 1、114、228、105 |
| D2 | 275 | 869 / 869 | 1、138、275、28（树 ID 169） |
| D3 | 439 | 1522 / 1522 | 1、220、439 |

- 对发布程序集中的最近相机算法，在 PowerShell 承载的 .NET `10.0.14` 中反射运行，与独立暴力基准全量对照 **942/942 棵一致**；用产品同源代码编译的 .NET `10.0.15` 测试程序也得到相同结果。实际自包含应用另做了下述抽样对照。该结论只适用于有完整位姿的全景帧，不保证树木可见。
- 共 78 条抽样状态检查通过，测试覆盖两种主帧策略、双帧状态、红圈角度、切帧、视角和校准；所比较的全景、照片、切图和热力图 JPEG 哈希差异为 0。
- 隔离副本中的人工标注保存、重载及 CSV 内容一致，角度舍入误差小于 `1e-5` 度；原元数据和标注文件 SHA-256 未变。原 ZIP 只核对了大小和修改时间，没有计算整包哈希。
- 抽样识别首选名称、可靠性和 Top 名称一致，概率差小于 `0.001`；对照表行在浮点容差内一致，CSV 字节一致。
- XLSX 可由 openpyxl 读取，工作表、表头、行列数、单元格类型和样式一致。由于运行时浮点格式和计算细节不同，工作表 XML 并非逐字节一致：D1 有 11 个数值单元格存在非零微差，最大约 `9.095e-13`；D2 为 33 个、D3 为 32 个，最大约 `3.320e-11`。这不是逐位一致性保证。
- JSON 协议异常与恢复、独立 Electron 界面、标注保存失败等检查通过。设置无效 `DOTNET_ROOT` 并从带空格的隔离路径启动自包含后端成功；这不是在全新 Windows 系统上的验证。
- 独立 QA 复制实际便携 EXE 后验证了默认加载、隔离数据的最近相机、识别和人工标注保存；原始标注哈希未变。检查 EXE 的 NSIS / 内层归档清单与前端资源后，未发现用户 CSV、INI、标注、全景 ZIP、回放日志或 PDB；包内桥接程序与受测后端、模型与项目模型的哈希一致。这不是对二进制内所有可能硬编码内容的完整隐私审计。

去除临时路径的机器可读摘要位于 `outputs/qa-dotnet10-20261112/report.json`。上述迁移对照不提供双帧红圈的人工真值准确率；实际定位仍应目视复核。
